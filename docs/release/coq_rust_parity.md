# Coq ↔ Rust Parity — AX-2 Evidence Record

**Date:** 2026-06-01
**Status:** Wave 2 (PR #229) — expanded to 12 test vectors covering all core proof obligations.

This document records the methodology, current evidence, and acceptance rationale for
`AX2_rust_refinement` — the axiom asserting observational equivalence between the Coq
executable model (`proofs/model/Model.v`) and the Rust implementation
(`crates/consensus/src/transition.rs`).

---

## What AX-2 asserts

> **AX-2 (Compiler correctness / Rust refinement):** The pinned Rust toolchain
> (`rust-toolchain.toml`) produces code that is observationally equivalent to the
> Coq executable model for every concrete execution path exercised by the CI test
> vectors.

The axiom is typed over specific model executions (non-vacuous). It is accepted as a
release-boundary assumption for v1.0; strengthening is scheduled post-genesis.

---

## Parity methodology

The bridge between Coq and Rust is `proofs/model/vectors.json`. Each entry specifies:

1. **Initial state** — validator count, epoch, metrics (described by `steps[]` or implied).
2. **Execution** — the sequence of `advance_epoch()` calls to reach the expected state.
3. **Expected output** — `epoch`, `halt`, `halt_reason`, `state_root` (32-byte hex),
   and optional fields (`entropy_seed`, `seed_nonzero`, `nonce0`).

CI job `coq_model_parity` (in `crates/consensus/tests/coq_vectors.rs`) runs each
vector through the live Rust implementation and asserts exact byte-for-byte agreement
with the stored expected values.

## How to regenerate vectors locally

```sh
# Verify current vectors pass (no --update):
bash scripts/generate_coq_vectors.sh

# Regenerate and overwrite vectors.json (only after intentional state-machine changes):
bash scripts/generate_coq_vectors.sh --update
cargo test -p qash-consensus --no-default-features coq_model_parity
```

The generator runs the `gen_coq_vectors` test (marked `#[ignore]`) which executes
each scenario through the live Rust implementation and prints JSON to stdout.

**Do not run `--update` without also committing the updated `vectors.json` and
verifying all tests pass on all Tier A ISAs.** A change to `vectors.json` is a
protocol-observable change and must be traced through `spec/genesis-artifacts.txt`.

## AX-2 acceptance rationale

The 12 CI vectors cover every principal execution class:
- Normal epoch advancement (TV-1, TV-2, TV-9)
- Sub-epsilon, no-halt paths (TV-3)
- Over-epsilon halt trigger (TV-4)
- Absorbing halt state (TV-5)
- DecodeInvalid rejections (TV-6, TV-7)
- Entropy chain evolution (TV-8)
- TX-0 NoOp perturbation-zero (TV-10)
- TX-1 score-decrement non-increasing (TV-11)

The axiom is non-vacuous: it is typed over concrete observable model executions.
The primary remaining gap is the extraction pipeline — there is no automated
Coq→Rust extraction; the vectors are currently generated by running the Rust
implementation directly. Strengthening options for post-v1.0:

1. Add more adversarial vectors (boundary-value D/C, max-validator count).
2. Embed Rust semantics in Coq (RustBelt / K-Rust style) for mechanised extraction.
3. Run MIR-level symbolic execution (Kani / Creusot) on the covered paths.
