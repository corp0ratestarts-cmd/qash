### 1.2 TOE Overview

The Target of Evaluation (TOE) is **Domain A** of the QASH protocol:
`crates/consensus/` (`qash-consensus` crate, no\_std, no-alloc). Domain A
implements the deterministic epoch transition function, Lyapunov stability
enforcement, transaction prevalidation, causal fingerprinting, and
state-root commitment.

**Domain B** (`crates/pal/`) is explicitly **excluded** from the TOE. Domain B
provides hardware abstraction (time, network, attestation) and is subject to
separate evaluation if required by deployment.

### 1.3 TOE Usage

The TOE is a software library implementing a replicated state transition
calculus. It does not operate a network, manage keys, or perform I/O. It
receives `EpochInput` (validated by Domain B) and raw transaction bytes, and
produces a new `EpochState` together with a deterministic state root.

## 3. Security Problem Definition (ASE\_SPD)

### 3.1 Threats

**T.REPLAY**: An adversary replays old epoch inputs to cause state divergence
between honest nodes.  
*Countermeasure:* Nonce anti-replay and causal fingerprint chaining (CF-1..CF-4).

**T.DIVERGENCE**: An adversary causes two honest nodes to advance to different
states from the same input sequence.  
*Countermeasure:* Deterministic `advance_epoch` (proven replay-invariant across
x86\_64/aarch64/riscv64gc); Lyapunov confluence theorem (LC-2).

**T.OVERFLOW**: Arithmetic overflow corrupts state in a non-deterministic way.  
*Countermeasure:* All arithmetic is checked; overflow triggers absorbing halt
(proven by `safety/absorbing_halt.v`).

**T.POLLUTION**: Domain B non-deterministic data flows into Domain A computations.  
*Countermeasure:* `EffectToken<T>` boundary type; domain tripwire CI; Coq
proof `cap_token_schema.v`.

**T.HALT\_BYPASS**: An adversary prevents a diverged node from halting.  
*Countermeasure:* Lyapunov violation → absorbing halt (irreversible);
`HaltReason` is monotone (once set, cannot be cleared by transition logic).

### 3.2 Assumptions

**A.DOMAIN\_B**: Domain B (PAL) is operated by a trusted operator who correctly
isolates hardware attestation, does not forward unverified signatures, and
applies the `EffectToken` boundary discipline.

**A.GENESIS**: Genesis constants are fixed and identical across all authorized
nodes before the first epoch transition.

**A.ENTROPY**: The entropy seed at genesis was generated by a CSPRNG meeting
NIST SP 800-90B.

## 7. TOE Summary Specification (ASE\_TSS)

The TOE implements:

1. **Epoch transition** (`advance_epoch`, `transition.rs`): atomic two-phase
   commit — pre-commit (read-only) then commit (assignments only). Any error
   in pre-commit returns without state mutation.

2. **Lyapunov stability** (`lyapunov.rs`): weighted sum V = Σ(wD·D + wC·C)
   over validators plus slash penalty φ. Halts when V exceeds EPSILON or
   when the delta window (sliding window of V changes) exceeds the bound.

3. **Transaction prevalidation** (`transaction.rs`): single-pass parse →
   `Candidate` projection → insertion-sort by (sort\_key, tx\_id) →
   AdmissionProjection apply. No re-parse in the apply pass.

4. **Causal fingerprint** (`transition.rs`): H\_domain(CausalFingerprint,
   prev\_fp || epoch\_le || state\_root) chained over every epoch. Equal
   fingerprints imply equal histories (proved CF-1..CF-4).

5. **State root** (`transition.rs`): streaming SHA3-256 over canonical state
   encoding; byte-identical to buffered path (parity tests in CI).

6. **Genesis constants** (`params.rs`): SHA3-256 commitment to the full
   genesis parameter set; any change produces a distinct chain.
